# Приём заявок в Telegram

Форма «Записаться на приём» отправляет заявку на `/api/lead`, а функция
`functions/lead.mjs` пересылает её ботом [@amirDentBot](https://t.me/amirDentBot)
в Telegram.

```
браузер (форма)  ──POST /api/lead──▶  функция Netlify  ──sendMessage──▶  Telegram
                                      (токен, chat_id)
```

Функция нужна потому, что Netlify отдаёт только готовые файлы и не выполняет код
на сервере. Обратиться к Telegram прямо из страницы нельзя: токен бота виден
любому, кто откроет исходники сайта, и бота сразу угонят.

**Netlify не выполняет PHP** — поэтому приём заявок сделан на JavaScript. Раньше
здесь лежал `api/lead.php`; на Netlify он просто скачивался как текстовый файл,
и заявки не отправлялись.

## Развёртывание

**Перетаскиванием папки или архива в Netlify функция не подключается.** Так сайт
выкладывается как набор файлов: `lead.mjs` просто скачивается по ссылке, а
`/api/lead` отвечает 404 — это уже случалось. Годятся только два способа.

Подключить репозиторий (предпочтительно): Netlify → Site configuration → Build &
deploy → Link repository. Тогда каждый `git push` в `main` сам обновляет сайт.

Либо вручную из папки проекта:

```bash
npx netlify deploy --prod
```

Netlify попросит войти в браузере, затем соберёт и выложит и страницы, и функцию.

## Настройки перед первым запуском

В Netlify → Site configuration → Environment variables:

| Переменная          | Значение                                        |
| ------------------- | ----------------------------------------------- |
| `BOT_TOKEN`         | токен бота от @BotFather                        |
| `CHAT_ID`           | кому присылать заявки                           |
| `CMS_PASSWORD_HASH` | SHA-256 пароля админки                          |
| `CMS_LOGIN`         | логин админки (по умолчанию `admin`)            |

Без `BOT_TOKEN` и `CHAT_ID` функция заявок отвечает 500 и пишет об этом в журнал,
а форма предлагает посетителю WhatsApp и телефон.

## Админ-панель

`functions/cms.mjs` обслуживает три адреса:

| Адрес              | Что делает                                          |
| ------------------ | --------------------------------------------------- |
| `/api/cms/login`   | проверяет логин и пароль                            |
| `/api/cms/save`    | сохраняет контент (нужен пароль)                    |
| `/api/cms/content` | отдаёт сохранённый контент всем посетителям         |

Контент лежит в хранилище Netlify Blobs, а не в файле: файл в папке `site`
сервер перезаписать не может. Правило в `netlify.toml` подменяет прежний адрес
`/assets/content.json` на `/api/cms/content`, поэтому код страницы и админки
читает контент как раньше.

Браузер отправляет не пароль, а его SHA-256, и сравнение идёт на сервере. В
файлах сайта пароля нет: `site` публикуется целиком, любой файл оттуда
скачивается по прямой ссылке — именно так раньше был доступен и пароль, и
токен бота.

### Сменить пароль админки

```bash
npx netlify env:set CMS_PASSWORD_HASH "$(node -e "
  console.log(require('crypto').createHash('sha256').update(process.argv[1],'utf8').digest('hex'))
" 'НОВЫЙ_ПАРОЛЬ')" && npx netlify deploy --prod
```

Сам пароль никуда не записывается — только его хеш.

## Локальный запуск

```bash
cp .env.example .env   # вписать BOT_TOKEN и CHAT_ID
./serve.sh
```

Поднимает и страницы, и функцию на <http://localhost:8123> — то же поведение, что
на сайте. Файл `.env` в git не попадает. Нужен Node.js **20.12.2 или новее**: на более старых версиях функция не
запускается и форма показывает отказ, хотя на самом сайте всё работает.

## Почему токена нет в файлах

Раньше он лежал в `functions/settings.mjs`. Netlify публиковал корень проекта
целиком, поэтому файл скачивался по прямой ссылке — токен оказался доступен всем.
Теперь публикуется только папка `site`, функция лежит вне неё, а токен живёт
исключительно в переменных окружения.

Правило на будущее: в `site` не должно попадать ничего, кроме страниц сайта.

## Что делает функция

- принимает только POST с JSON, остальное отклоняет
- проверяет имя (от 2 символов) и телефон (не меньше 10 цифр)
- отбрасывает спам-ботов по скрытому полю `company` в форме
- экранирует данные перед отправкой в Telegram
- если Telegram не принял заявку, пишет её в журнал функции (Netlify → Logs →
  Functions), чтобы заявку можно было найти вручную; посетителю форма в этот
  момент предлагает WhatsApp и телефон

## Как узнать chat_id

Написать боту `/start`, затем открыть

```
https://api.telegram.org/bot<ТОКЕН>/getUpdates
```

и взять значение `result[0].message.chat.id`. Чтобы заявки видели несколько
администраторов, можно создать группу, добавить в неё бота и указать
идентификатор группы (он начинается с `-100`).
