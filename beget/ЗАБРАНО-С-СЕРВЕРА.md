# Боевой backend, забранный с Beget

Снято 6 августа 2026 с `stuzzh0s@stuzzh0s.beget.tech:~/stuzzh0s.beget.tech/amirdent/`
**как есть, без правок.** Это код, который реально обслуживает продакшен.

## Что внутри

| Файл | Что это |
|---|---|
| `server.mjs` | Node-сервер под Phusion Passenger: статика, `/api/lead`, `/api/health`, `/api/cms/*` |
| `doctor_rating.py` | Модуль подбора рейтингов, вызывается из CLI |
| `doctor-rating-cli.py` | Обёртка, которую server.mjs запускает как подпроцесс |
| `.env.example` | Шаблон переменных: `CMS_LOGIN`, `CMS_PASSWORD_HASH`, `BOT_TOKEN`, `CHAT_ID`, `HEALTH_TOKEN`, `PYTHON_BIN` |
| `.htaccess.example` | Как Passenger поднимает приложение |
| `beget-manifest.json`, `README.md` | Сопровождение с сервера |

## Что намеренно НЕ забрано

- **`.env`** — реальные секреты. Остаётся только на сервере.
- **`storage/`** — рабочие данные: `leads/` (реальные заявки пациентов,
  персональные данные), `sessions/`, `media/`, `lead-rate/`, `login-rate/`.
- **`node`** — бинарник 103 МБ.
- **`site/`** — собранная статика, генерируется из репозитория.

## Ключевой факт

Авторизация `doctor-rating` **здесь исправлена**: `handleCms` вызывает
`authenticate(req)` (сессионная cookie) и отдаёт `401` без сессии, а
`cmsDoctorRating` не проверяет `X-CMS-Token` вообще. Сломана только прежняя
реализация в `netlify/functions/doctor-rating.mjs`, которая на проде не работает.
