## Критично

### B1. CMS перезаписывает «зачищённые» тексты старой рекламной копией

Коммит `07e504c` («Harden site for production launch») смягчил формулировки в
HTML, но `content.json` хранит старые тексты и перекрывает вёрстку в рантайме.

Для медицинских услуг «без боли» и «гарантия результата» — рискованные
утверждения (ст. 24 ФЗ «О рекламе»). Правка в HTML не даёт эффекта, пока не
обновлён `content.json`.

- [x] Решить, было ли смягчение формулировок осознанным юридическим решением.
      Принято: оставляем смягчённые формулировки из `07e504c` (юридически
      безопаснее для медрекламы).
- [x] Привести `content.json` в соответствие с выбранным вариантом.
      В `textItems`: hero-sub, why-grid cap и два `.chip` → «Бережное лечение»,
      «План и смета», формулировка про врачей и смету.

### B2. Заголовок блока карты не соответствует содержимому

В `site/index.html:204` написано «Как нас найти», но над Яндекс-картой
отображается:

> ### Результаты до и после
> Потяните ползунок, чтобы увидеть разницу.

Причина — `textItems` в `content.json` адресуют блоки по позиции:
`{"sel":"section.pad > .container > .sec-title > h2","idx":3}`. Когда блок
«до/после» удалили, индексы сдвинулись, и текст удалённой секции сел на секцию
карты.

- [x] Убрать осиротевшие записи `textItems` с индексами удалённых секций.
- [x] Перевести адресацию на стабильные `id` / `data-cms` якоря — позиционные
      селекторы будут ломаться при каждом изменении структуры страницы.
      (`data-cms-text` на секциях главной + `TEXT_SELECTORS` в `cms.js` без
      `section.pad … idx`; map-title/map-sub = «Как нас найти».)

### B3. 20 страниц услуг отдают одинаковый placeholder

Все `site/uslugi/*/index.html` содержат буквально `<h1 id="dirTitle">Услуга</h1>`
и пустой `<p id="dirDesc">`. Заголовок и описание подставляет `service.js` уже в
браузере (`site/assets/service.js:261`). `<title>` и `<meta description>` при
этом уникальны — то есть в индекс попадают 20 URL с уникальными сниппетами и
идентичным видимым контентом.

- [x] Вшивать заголовок, описание и хлебные крошки в HTML на этапе
      `scripts/build-site.mjs` — данные там уже есть.
      (`dirTitle`, `dirDesc`, `dirCrumb`, `dirGroup` из `services-data.js`.)

## Важно

### B4. Каждый посетитель тянет админский движок

На всех публичных страницах подключён `cms.js` (123 КБ), который на старте:

- грузит `/assets/content.json?ts=…` с `cache:'no-store'` → редирект на функцию
  `/api/cms/content` (228 КБ, некэшируемо, вызов функции на каждый просмотр);
- пишет ~150 КБ в `localStorage` анонимному посетителю (замерено: 152 760 байт);
- дёргает `/api/cms/session` — ещё один вызов функции на каждый просмотр.

Итого ~350 КБ некэшируемого трафика и 2 serverless-вызова на просмотр, плюс
мигание контента: прайс сначала рендерится из 121 КБ статики в `prices.html`,
потом целиком заменяется.

- [x] Грузить `cms.js` и контент только при активной сессии администратора.
      (`cms-boot.js` подключает CMS лишь в режиме правки после `/admin.html`.)
- [x] Публиковать контент в статику на этапе билда.
      (`content.json` отдаётся как статика; билд синкает из API/blobs + `prices.html`.)

### B5. Автоподбор рейтинга врача в админке мёртв

`cms.js` шлёт `X-CMS-Token: AmirCMS.getToken()`, а `getToken()` после перехода
на cookie-сессии возвращает строку-заглушку `'cookie-session'`
(`site/assets/cms-auth.js:70`). `doctor-rating.mjs` сверяет этот токен с
`CMS_PASSWORD_HASH` (`netlify/functions/doctor-rating.mjs:444`) → всегда `401`.

- [ ] Перевести `doctor-rating.mjs` на проверку сессионной cookie, как в
      остальных ручках CMS.
- [ ] Расширить `tests/security.test.mjs:13` на `cms.js` — сейчас тест
      проверяет отсутствие `X-CMS-Token` только в `cms-auth.js`, а заголовок
      шлёт `cms.js`, поэтому тест зелёный при сломанной функции.

### B6. Блок «Видеоотзывы» — пустышка

> Здесь будет видео. Добавьте ссылку в атрибут data-video (VK Видео, Rutube,
> YouTube) или файл .mp4

При неотправленном уведомлении `lead.mjs` возвращает `202 {ok:true}`, и форма

просмотра нет — то есть никто не узнает.

- [x] Сделать просмотр заявок в админке либо резервный канал уведомления.
      (Панель «Заявки» в CMS + `/api/cms/leads`; форма честно пишет «сохранена»,
      если Telegram не отправил.)

### B13. Сессии CMS не чистятся

`sessions/*` в блобах пишутся при каждом входе и удаляются только при явном
logout; истёкшие остаются навсегда. `maintenance.mjs` делает бэкап, но не
сборку мусора.

- [x] Добавить очистку истёкших сессий в `maintenance.mjs`.
      (Ежедневный GC: `list(sessions/*)` → delete без `expiresAt` или с
      `expiresAt <= now`; GC идёт до бэкапа, даже если content отсутствует.)

### B14. Лишние редиректы в навигации

Логотип и «Главная» на главной ведут на `index.html`, который `netlify.toml:63`
отдаёт 301 на `/`. В выпадающем меню — `/prices.html` → 301 на `/prices`, при
том что кнопка ниже уже ведёт на `/prices`.

- [x] Проставить конечные адреса.
      (Главная/логотип → `/`; прайс и ссылки «полный прайс» → `/prices`.)

### B15. Мёртвая разметка в шапке

`/#services` с `data-nav-cat`, которое `menu.js` полностью затирает. Без JS
